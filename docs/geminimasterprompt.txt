1.21.11 YARN LANDMINES I ALREADY SOLVED (trust these, they are tested)
================================================================================
- There is NO SwordItem class in 1.21.11 — swords are plain items. Detect
  them with stack.isIn(ItemTags.SWORDS). Axes: instanceof AxeItem (still
  exists). Elytra is a plain Items.ELYTRA item.
- Mouse.updateMouse(double delta) takes a frame-delta parameter now. To add
  rotation on top of the player's own mouse movement, @Inject at HEAD of
  updateMouse, adjust the @Shadow cursorDeltaX/cursorDeltaY and write them
  back — that preserves the player's real input and looks human.
- Client tick events (ClientTickEvents.END_CLIENT_TICK) run AFTER
  ClientPlayerEntity.tick(). If you switch hotbar slots and attack in the
  same tick, the vanilla slot packet is sent too late — the server resolves
  the attack with the OLD item. Fix: after setSelectedSlot(), also send
  networkHandler.sendPacket(new UpdateSelectedSlotC2SPacket(slot)).
- Hooking the player's own attacks: @Inject at HEAD of
  ClientPlayerInteractionManager.attackEntity(PlayerEntity, Entity).
- Gliding state: player.isGliding(). Fall distance: player.fallDistance.
- Shield actually raised: entity.isBlocking() &&
  entity.getActiveItem().getItem() == Items.SHIELD.
- Enchantments in 1.21.11: EnchantmentHelper.getEnchantments(stack) returns
  entries whose key is Optional<RegistryKey<Enchantment>> — match by
  key.getValue().getPath() containing "breach" / "density" / "lunge" /
  "wind_burst".
- Armor swap without a screen: interactionManager.clickSlot(syncId, 6,
  hotbarSlot, SlotActionType.SWAP, player) — screen slot 6 = chest armor;
  works outside any GUI, same as pressing F in the inventory.
- The client cancels held item use when the use key reads not-pressed. If
  you ever hold the use key for a feature, you MUST release it only when
  you were the one who pressed it, or you will break eating for the player.

FEATURE SPECS
--------------------------------------------------------------------------------

AIM ASSIST
  Smooth mode reproduces the Wurst client's AimAssist feel exactly:
  - Per-tick rotation budget = speed/20 degrees.
  - Split the budget between yaw and pitch proportional to how far each
    axis still has to turn; clamp each axis to its share; wrap-aware
    angles.
  - Apply the rotation as an additive delta on top of my real mouse input
    (through the mouse pipeline, see landmine #2) so it looks human.
  - If under 1 degree away but not on the hitbox, exaggerate by 1 degree
    so the crosshair actually lands on it.
  - Target = nearest valid entity (honoring the target toggles) within
    range whose angle from my crosshair is within FOV/2.
  Max mode: snap onto the aim point instantly every tick. No smoothing,
  jitter is fine.
  Aim points (Wurst-exact): Head = target eye height; Center = bounding box
  center; Feet = position + 0.001; Auto = closest point of the target's
  hitbox to my eyes (eye position clamped onto the box).
  "Activation" for speed randomization = the moment the assist engages a
  target (no target -> target). Switching targets or re-engaging after a
  loss is a NEW activation with a NEW roll. Never re-roll per tick.

ATTRIBUTESWAP
  Trigger: I land a hit while holding a SWORD, an AXE, a SPEAR WITHOUT the
  Lunge enchantment, or an EMPTY HAND. Nothing else triggers it. Any
  material (netherite, diamond, iron, copper, wood...).
  Normal case (I am grounded, jumping, or less than 3 blocks above the
  target — or the target is HIGHER than me): in the SAME TICK as the
  triggering hit, switch to the mace with Breach (I-IV), attack with it the
  SAME tick, then switch back to my originally held item within the next
  1-4 ticks (randomized).
  Falling case (I am 3+ blocks above the target): compute within
  milliseconds which mace in my hotbar deals the MOST damage for this hit
  (each mace's own enchants: Density +0.5 dmg/block fallen/level; Breach
  -15% armor/level; they never coexist on one mace; base smash bonus
  +4 HP/block first 3 blocks, +2 HP/block next 5, +1 HP/block beyond).
  Then same-tick swap to that best mace, hit same tick, swap back within
  1-4 randomized ticks.
  Requires a qualifying mace in the hotbar or nothing happens.

STUN SLAM
  Constantly checks the player under my crosshair. Shield NOT raised: do
  nothing. Shield raised:
  - I am on ground / jumping / under 3 blocks above target, and I attack:
    same tick switch to an axe, axe hit lands same tick OR next tick
    (random 0-1 tick delay), switch back to my held item.
  - I am 3+ blocks above target and I attack: same tick switch to axe,
    land 4-5 axe hits within the next 0-1 ticks, switch to the best-damage
    mace (AttributeSwap's calculator), land 5-6 mace hits within the next
    2-3 ticks, then next tick switch back to the original item.
  Purpose: an axe hit on a raised shield disables that shield for 5
  seconds. Requires an axe (plus a mace for the falling case) in hotbar.
  COLLISION: if Shield Draining is enabled and the target's shield is up,
  Stun Slam must NOT run — Shield Draining takes over completely.

PEARL CATCH
  Watches for MY OWN ender pearl being thrown (check the pearl's owner —
  enemy and teammate pearls are IGNORED) whose arc will rise more than 10
  blocks (heights from player positions, not the ground).
  Automatic mode: simulate both trajectories precisely; solve where a wind
  charge thrown after the configured delay (1-3 ticks) will meet the
  pearl; instantly snap my camera onto the throw direction (no smoothing)
  and throw the wind charge at exactly the right tick so it collides with
  the pearl mid-air. ONE wind-charge throw per pearl, no retry on a miss.
  Manual mode: qualifying pearl detected -> just throw the wind charge
  after the configured delay. No camera movement, no math.
  Requires a wind charge in the hotbar.

SHIELD DRAINING
  Conditions: I am 3+ blocks above the target, target's shield raised,
  target within attack range, a mace in the hotbar.
  Behavior: without waiting for any click from me, auto-spam the
  best-damage mace at the configured CPS (20-250, default 50), starting
  the SAME TICK the target enters attack range (a real client cannot
  attack out of range — no "early" start), continuing while the shield
  stays up. Rationale: every blocked 3+ HP hit costs the shield durability
  equal to the attack damage — high-CPS falling mace hits shred a
  336-durability shield near-instantly.
  While active it owns ALL attack output against that shielded target:
  Stun Slam's axe phase suppressed, Auto Mace's attack phase suppressed
  (they only provide aim). No axe hits while draining — the shield staying
  up is the point.

ALWAYS-ON SHIELD (my anti elytra-macer defense)
  Continuously scans a hemisphere 8 blocks wide centered at my level for
  players falling or gliding 3+ blocks above me (relative heights; works
  while I am in the air too).
  When found: instantly snap-lock my aim onto them, raise and hold the
  shield while looking at them (a REAL use-key hold, no packets; input
  ownership rules apply). Keep holding until the threat descends to 2
  blocks above my level (mace smash stops being possible below 1.5 blocks
  of height advantage), then release and resume scanning.
  TRIGGERED-STATE RULE: while TRIGGERED (threat engaged, shield held), NO
  other feature may switch slots or attack — all their actions are
  suspended until the hold ends. Do NOT implement "drop the shield for my
  own swing" — I rejected that.
  My manual input is never blocked: a manual slot switch ends the hold and
  my slot choice WINS (never yank the selection back).
  Requires a shield in the hotbar or the offhand.

ELYTRA MACE (the flagship)
  Requires: I am gliding with an elytra (firework boost optional), and
  both an elytra and a chestplate are in the hotbar. While gliding, Auto
  Mace stays idle — it is a falling-state feature.
  AutoAim ON: while gliding, scan the hemisphere BELOW me inside the
  configured FOV (60-360, default 180). When a player is detected, engage
  this feature's own aim (Smooth or Instant). The moment the target is on
  my crosshair:
    1) in the FIRST TICK of the engagement: swap the equipped elytra for
       the chestplate by selecting the chestplate's hotbar slot and using
       it (right-click) — a REAL equipment swap, no packets;
    2) then, if the target's shield is up: switch to the axe slot and hit
       5-6 times within 1 tick, then switch to the best-damage mace and
       spam 5-6 hits within the next 2 ticks, then end and release the aim;
    3) if no shield: skip the axe, straight to the best-mace spam.
  AutoAim OFF: no scanning; while gliding 3+ blocks above a target, wait
  until the target crosses my crosshair, then run the same sequence
  (elytra->chestplate swap first, in tick 1).
  The aim is released after each engagement; the feature stays enabled and
  re-arms for the next target.

AUTO MACE (Elytra Mace's attack sequence without the elytra part — the
single falling-attack feature)
  Triggers only while I am FALLING (not gliding) from 3+ blocks above a
  target — already falling means the smash already counts and NO
  elytra/chestplate swap happens.
  Auto aim ON: scan the hemisphere below me inside the configured FOV
  (60-360, default 180), engage the selected aim type (Smooth/Instant).
  Auto aim OFF: wait until the target crosses my crosshair.
  The moment the target is on my crosshair, run Elytra Mace's exact burst:
    - shield up: axe 5-6 hits within 1 tick, then best-damage mace 5-6
      hits within the next 2 ticks, then release the aim — done;
    - shield down: best-damage mace directly, same 5-6-hit burst, release.
  ONE precise burst per engagement — no continued spam afterwards. (If
  Shield Draining is active against the shielded target, it owns the
  attacks at its CPS and Auto Mace provides aim only.)
  Release the aim when done; stay enabled and re-arm.
  Requires a mace in the hotbar (plus an axe for the shield path).

COLLISION RULES (who wins when two features could react to the same moment)
--------------------------------------------------------------------------------
1. Master kill switch off -> everything inert except the mod menu itself.
2. Gliding state -> only Elytra Mace may engage; Auto Mace stays idle.
3. Falling state -> Auto Mace owns the engagement (only falling feature).
4. Always-On Shield TRIGGERED -> ALL other features suspended (no slot
   switches, no attacks) until the hold ends (threat released at +2,
   feature toggled off, or I manually switch slots).
5. Target's shield up + Shield Draining enabled -> Shield Draining owns
   ALL attack output at its CPS; Stun Slam axe phase and Auto Mace attack
   phase suppressed; the engaging feature provides aim only; no axe hits
   while draining.
6. A feature running its own aim (Elytra Mace, Auto Mace, Always-On
   Shield, Pearl Catch snap) suspends the global Aim Assist until it
   releases the aim state; every feature MUST release it when done.
7. Attribute Swap and Stun Slam on the same hit: Attribute Swap owns the
   same-tick swap chain; Stun Slam queues behind it — one swap chain, no
   slot flicker.
8. Pearl Catch's instant snap fires immediately even if a combat aim is
   active; the combat aim re-engages right after the throw.
9. My manual input ALWAYS wins: a manual slot switch ends an Always-On
   Shield hold with my slot kept; never yank slots or keys from under me.
