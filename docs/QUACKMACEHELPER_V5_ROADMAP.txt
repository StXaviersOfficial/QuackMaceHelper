SECTION 0 - GLOBAL RULES (apply to EVERY feature, no exceptions)
================================================================================
R1. MASTER KILL SWITCH: first setting of General. When OFF the mod must behave
    as if it never existed: no feature ticks, no mixins act, no HUD, no
    feature keybinds respond. ONLY the mod-menu open key (and the ModMenu
    entry) stay alive so the mod can be re-enabled in-game. When ON, only
    features whose own toggles are ON run.
R2. REAL PLAYER ACTIONS ONLY (STRICT): every action must go through the real
    client code paths - real selected-slot changes, real attack calls
    (ClientPlayerInteractionManager.attackEntity), real item use, real shield
    use. NEVER handcraft/spam raw packets. The server must only ever see what
    a legit player client would send.
R3. PLAYER-POSITION MEASUREMENTS (STRICT): all distances, heights and angles
    are measured from PLAYER positions (eye / feet), never from the ground
    under them. "Falling from above 3 blocks" = the ATTACKER'S height minus
    the TARGET'S height (both as body positions) >= 3 blocks, not the fall
    distance counter, unless a feature explicitly says fall distance.
R4. HOTBAR REQUIREMENTS: a feature only activates if its required items are in
    the hotbar (any slot; AlwaysOnShield may also use the offhand):
      - PearlCatch ........ wind charge
      - ElytraMace ........ elytra AND chestplate
      - StunSlam .......... axe (plus a mace for the 3+-block path)
      - AttributeSwap ..... mace (breach mace for the normal path)
      - ShieldDraining .... mace
      - AutoMaze .......... mace (plus an axe for the shield path)
      - AutoMace .......... mace (plus an axe for the shield path)
      - AlwaysOnShield .... shield in the hotbar OR the offhand
R5. NO COLLISIONS: features must not fight each other (see collision matrix,
    Section 2).
R6. Every toggle, keybind and selector must actually work; verify each one.
R7. All keybinds default UNBOUND except the open-menu key.
R8. All mechanics researched and verified on Minecraft 1.21.11 specifically.

SECTION 1 - MENU STRUCTURE (exact top-to-bottom order)
================================================================================
GENERAL
  1. MASTER KILL SWITCH (on/off)                 [NEW in V5]
  2. Target players / mobs / animals             (existing, unchanged)
  3. Open menu key                               (existing, unchanged)

AIM ASSIST
  - On/off switch
  - Toggle keybind (unbound by default)
  - Range selector: 0.1 - 8 blocks
  - FOV selector (cone from the crosshair): 1-360 degrees, default 360
  - Speed (degrees per second; 3600 default - CONFIRMED by boss)
  - Speed randomization (ON by default): when the assist ACTIVATES, roll one
    random value in [0, 200], add OR subtract it from the speed, and hold
    that adjusted speed for the whole activation (CONFIRMED: once per
    activation, NOT per tick). Clamp the result to a 10 deg/s floor so it can
    never drop to zero or below.
  - Mode: Smooth (default) | Max
      Smooth = Wurst-style smooth rotation (algorithm in Section 3)
      Max    = instant snap-lock onto the aim point every tick; jitter is
               acceptable, no smoothing at all
  - Aim At: Head | Center | Feet | Auto
      Auto = Wurst-style closest point of the target hitbox to the player's
      eyes (4th option ADDED per boss answer Q4)

ATTRIBUTESWAP (replaces the old "BreachSwap")
  - On/off switch, toggle keybind (unbound)
  - TRIGGER ITEMS: sword (any material), axe, spear WITHOUT Lunge enchantment,
    or EMPTY HAND - nothing else triggers it (a spear WITH Lunge never
    triggers; bows/crossbows/tridents/etc never trigger).
  - NORMAL CASE (user on ground / jumping / falling less than 3 blocks above
    target, OR target is HIGHER than user): the SAME TICK the user's hit lands
    with a trigger item -> switch to the mace with BREACH (I-IV) -> use the
    real attack the SAME tick -> switch back to the original item within the
    next 1-4 ticks (randomized).
  - FALLING CASE (user 3+ blocks ABOVE the target, see R3): calculate which
    mace in the hotbar deals the MOST damage (fall distance + Density /
    Breach levels + base damage; math in Section 3) - calculation must run in
    milliseconds - then same-tick swap -> hit -> swap back within 1-4 ticks.
  - If target is higher than user: always the plain breach-mace path (Density
    and Wind Burst do nothing from below).

STUN SLAM ("stone slamming")
  - On/off switch, toggle keybind (unbound)
  - Constantly watches the player currently UNDER THE CROSSHAIR for a raised
    shield. No shield -> feature does nothing at all.
  - Shield UP, user on ground / jumping / falling < 3 blocks above target,
    user attacks: same tick switch to axe -> axe hit lands same tick OR next
    tick (randomly 0 or 1 tick delay) -> switch back to the held item.
  - Shield UP, user falling 3+ blocks above target, user attacks:
    same tick switch to axe -> 4-5 axe hits inside the next 0-1 ticks ->
    switch to the best-damage mace (calculated) -> 5-6 mace hits inside the
    next 2-3 ticks (spam) -> next tick switch back to the original item.
  - COLLISION RULE: if ShieldDraining is enabled AND the target's shield is
    up, StunSlam must NOT run its axe phase at all - ShieldDraining takes
    over (mace spam only, at its CPS). Applies to both height cases.

PEARL CATCH
  - On/off switch, toggle keybind (unbound)
  - Mode: Automatic (default) | Manual
  - Delay selector: 1-3 ticks
  - Trigger: THE USER'S OWN ender pearl is thrown (CONFIRMED, Q3: check the
    pearl's owner - enemy and teammate pearls are IGNORED) and its trajectory
    will exceed 10 blocks of height (measured from PLAYER positions, R3).
  - AUTOMATIC mode: predict exactly where the pearl will be when a wind
    charge thrown NOW (after the selected delay) would reach it - full
    projectile simulation, super precise - then INSTANTLY snap the camera to
    the throw solution (no smooth movement) and throw the wind charge at the
    selected delay. The wind charge must collide with the pearl mid-air.
  - MANUAL mode: when a qualifying pearl is detected, just throw the wind
    charge at the selected delay - no camera movement, no intercept math.
  - ONE wind-charge throw per pearl; no retry if the intercept somehow misses
    (Q13 pending).
  - Requires wind charge in hotbar (R4).

SHIELD DRAINING
  - On/off switch, toggle keybind (unbound)
  - CPS selector: 20 to 250, DEFAULT 50 (CONFIRMED, Q8)
  - Conditions: user 3+ blocks above the target (R3) AND target's shield is
    raised AND target in attack range AND a mace is in the hotbar.
  - Behavior: WITHOUT the user clicking anything, auto-spam the best-damage
    mace (calculated) at the selected CPS, starting the SAME TICK the target
    enters attack range (NOTE: the old "1-2 ticks early" idea was impossible
    for a real client - you cannot attack out of range - and is dropped).
    Works because every blocked hit drains shield durability equal to the
    attack damage (Section 3).
  - While active it owns ALL attack output against that shielded target:
    StunSlam's axe phase is suppressed, and AutoMaze / AutoMace attack phases
    are suppressed too (they only provide aim in that case). No axe hits
    while draining - the shield staying up is the point.

ALWAYS-ON SHIELD (anti elytra-macer defense)
  - On/off switch, toggle keybind (unbound)
  - Constantly scans a hemisphere 8 blocks wide around the user's level for
    players who are falling from 3+ blocks above the user OR gliding 3+
    blocks above the user (R3, relative heights; also works while the user is
    in the air).
  - On detection: instant snap-aim (lock) at the threat, hold the shield up
    while looking at them, keep holding while they fall. The hold is a REAL
    use-key hold (no packets).
  - Requires a shield in the hotbar OR the offhand (R4).
  - Release when the threat descends to user level +2 blocks (locked per Q6
    "yes" = the safe option; mace smash needs 1.5+ blocks of height
    advantage - see Q14 to switch to +1 if you meant that).
  - If the user attacks while the shield is being held: drop the shield for
    the swing, re-raise while the threat persists (Q12 pending).

ELYTRA MACE (replaces the old "ElytraSwapper") - MOST IMPORTANT FEATURE
  - On/off switch, toggle keybind (unbound)
  - AimAssist type selector: Smooth | Instant
  - AutoAim: on/off
  - FOV selector: 60 - 360 degrees, default 360
  - ACTIVATION REQUIRES the user gliding with an elytra (firework boost
    optional). While gliding, AutoMaze and AutoMace stay idle (collision
    matrix) - they are FALLING features.
  - AUTOAIM ON: while gliding, scan a hemisphere BELOW the user inside the
    selected FOV; when a player is detected, engage the aim assist with the
    selected type (smooth or instant). Once the target is ON the crosshair:
      1) swap elytra -> chestplate by selecting the chestplate's HOTBAR slot
         and right-clicking it (real equipment swap - NOT packets);
      2) IF the target's shield is up: switch to the axe slot, hit with the
         axe 5-6 times within 1 tick, then switch to the best-damage mace
         (calculated) and spam it 5-6 times within the next 2 ticks, then the
         engagement ends and this feature's aim is released;
      3) IF no shield: go straight to the mace (same spam pattern).
  - AUTOAIM OFF: no hemisphere scan; instead, while gliding 3+ blocks above a
    target (R3), wait until the target crosses the crosshair, then run the
    same swap/attack sequence (elytra->chestplate, shield check, axe/mace).
  - The aim is released after EACH engagement; the feature itself stays
    enabled and re-arms for the next target.
  - Requires elytra AND chestplate in hotbar (R4).

AUTO MAZE (was "Billiard" in the dictation; behaves like the boss's "Elite
Maze" reference but must NOT be an exact copy)
  - On/off switch, toggle keybind (unbound)
  - Auto aim: on/off
  - Aim type: Smooth | Instant
  - FOV selector: 60 - 360 degrees, default 360
  - Behavior:
    1) user is FALLING (not gliding, not grounded) from 3+ blocks above a
       target (R3);
    2) create a hemisphere BELOW the player and check for a target inside the
       selected FOV;
    3) if auto aim is on, engage the selected aim type;
    4) when the target is on the cursor, perform the attack. No chestplate
       swap needed here - the smash bonus already counts while falling;
    5) target shield up  -> axe spam, then best-damage mace spam (UNLESS
       ShieldDraining owns the attacks - collision matrix; then AutoMaze
       provides aim only);
    6) target shield down-> direct mace spam, KEPT UP until the smash bonus
       stops counting (that continuous spam is the Elite-Maze feel);
    7) release the aim when the engagement ends; feature stays enabled.
  - Requires a mace in the hotbar (plus an axe for the shield path).

AUTO MACE (NEW feature - boss: "basically ElytraMace, but not exactly that";
interpretation below is what got built into the master prompt - final confirm
is Q9)
  - On/off switch, toggle keybind (unbound)
  - Auto aim: on/off
  - Aim type: Smooth | Instant
  - FOV selector: 60 - 360 degrees, default 360
  - Behavior: the ElytraMace attack sequence WITHOUT gliding and WITHOUT the
    elytra->chestplate swap (you are already falling, so the smash already
    counts):
    1) user is FALLING (not gliding) 3+ blocks above a target (R3);
    2) hemisphere BELOW the player + FOV scan; autoaim per settings (AutoAim
       OFF = wait for the target to cross the crosshair, like ElytraMace);
    3) on lock, IF the target's shield is up: axe 5-6 hits within 1 tick ->
       best-damage mace (calculated) 5-6 hits within the next 2 ticks ->
       release the aim, engagement done (unless ShieldDraining owns the
       attacks - collision matrix);
    4) on lock, IF no shield: best-damage mace directly, same 5-6-hit burst,
       then release;
    5) ONE precise burst per engagement - unlike AutoMaze it does NOT keep
       spamming until the smash bonus ends. That burst-vs-continuous split is
       the AutoMace/AutoMaze difference (Q9).
  - Requires a mace in the hotbar (plus an axe for the shield path).

WIND TACKLE
  - Current WindChargeTackle code is DELETED. The bottom-most menu entry is a
    dead "WindTackle - coming soon" button that does nothing.

  nothing is ever left stuck.

  the same-tick swap; StunSlam must queue behind it (single swap chain, no

  active; the combat aim re-engages right after the throw.
- AlwaysOnShield holding + the user attacks -> drop the shield for the swing,
  re-raise while the threat persists (Q12 proposal).

SECTION 3 - VERIFIED MECHANICS RESEARCH (Minecraft 1.21.11)
================================================================================
MACE (minecraft.wiki/w/Mace):
  - Smash attack: attacker must have fallen >= 1.5 blocks and not be
    grounded/elytra-flying at the hit. Extra damage: +4 HP per block for the
    first 3 blocks fallen, +2 HP per block for the next 5, +1 HP per block
    after that. Usually also a critical hit (+50%).
  - Successful smash resets fall height -> no fall damage taken.
  - Attack range 3 blocks. Base damage 6 (smash stacks on top).
  - Density (I-V): +0.5 damage per block fallen per level. Smash-only.
  - Breach (I-IV): target armor effectiveness -15% per level.
  - Density and Breach are MUTUALLY EXCLUSIVE on one mace -> the
    best-damage calculator must evaluate each mace with its own enchants.
  - Wind Burst (I-III): launches the attacker upward after a smash (~7-8
    blocks per level) - enables chained smashes; does not negate fall damage.
SHIELD (minecraft.wiki/w/Shield):
  - Durability 336. A blocked attack of 3+ HP costs the shield durability
    equal to the attack's damage (rounded up) -> THIS is why ShieldDraining
    works: 50+ CPS of falling mace hits (huge per-hit damage) shreds 336
    durability near-instantly.
  - An axe hit on a fully-raised shield disables that shield for 5 seconds
    (100 ticks) -> this is the StunSlam axe phase's purpose.
  - Shield must be fully up (past its 5-tick raise delay) to be disabled.
SPEAR + LUNGE (1.21.11 "Mounts of Mayhem" content, confirmed):
  - Spears exist; Lunge (I-III) propels the wielder forward on a jab, costs
    saturation. -> AttributeSwap triggers on spears WITHOUT Lunge only.
WIND CHARGE + PEARL (confirmed tech, MC-268407 + "ender catch" community tech):
  - Wind charges collide with ender pearls mid-air and knock them off course
    -> PearlCatch's intercept is physically possible.
WURST AIM ASSIST (read from Wurst7 source, GPL-3):
  - Per-tick rotation budget = speed_deg_per_sec / 20.
  - slowlyTurnTowards(): split the budget between yaw and pitch in proportion
    to how far each still has to go (yawChange vs pitchChange ratio), clamp
    each axis to its share (limitAngleChange, wrap-degree aware).
  - The assist ADDS its delta on top of the player's real mouse input (mouse
    pipeline injection) so rotations look completely natural - this is the
    smoothness we want in Smooth mode.
  - If less than 1 degree off but not on the hitbox, exaggerate by 1 degree
    to actually land on it.
  - FOV check = angle between current look and the needed rotation <= FOV/2.
  - Aim points: Head = eye height; Center = bounding box center;
    Feet = position + 0.001; Auto = closest point of the hitbox to the
    player's eyes (clamped eye position onto the box).
INPUT-RATE REALITY (ShieldDraining CPS, StunSlam/AutoMace burst hits):
  - CPS above 20 means several REAL attack calls inside one game tick. That
    is still a genuine client action (each call produces one vanilla
    InteractPacket through the interaction manager) - no raw packets needed,
    R2 stays intact. To a server it looks like an autoclicker; that is
    inherent to what these features are.
